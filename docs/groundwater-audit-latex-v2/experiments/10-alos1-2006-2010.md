# 10 ALOS-1 PALSAR 2006-2010 (DGX Spark)

## Question
Was the same sinking pattern present in 2006-10, when the PANGAEA wells were sampled? Do the wells
sit on sinking ground in that period?

## Processing
- Data: ALOS-1 PALSAR L1.0, path 431 (ascending), 2006-12-06 .. 2010-11-01, from ASF. In this run
  the raw scenes had already been downloaded and cropped in WSL on the laptop, so ~9 GB of raw data
  per date was streamed to the Spark (`alos_xfer_spark.sh`, ~2 h over a relayed Tailscale link) and
  focused there (`alos_pipeline_spark.sh`). For a rerun, download directly on the Spark with
  `alos_download_spark.py` + `alos_full_spark.sh` (uses the user's `~/.netrc` there).
- Scripts (in `../code/`): `alos_search.py`, `alos_dem.sh`, `alos_stack.sh`, `alos_run_par.sh`,
  `alos_build_isce_aarch64.sh`, `alos_fix_paths.py`, `alos_extract.py`, `alos_analyze.py`, `alos_report.py`.
- Machine: DGX Spark (aarch64) over Tailscale, work dir `~/alos_work` (~126 GB of intermediates).
- Software: ISCE2 v2.6.5 built from source (no aarch64 package): autoRIFT disabled (needs the
  OpenCV C API removed in OpenCV 5), `-std=gnu17` for GCC 15, stripmapStack copied in by hand;
  SNAPHU from ISCE's `contrib`. micromamba env `alos`.
- Fixes: path rewriting inside pickled shelve files (`alos_fix_paths.py`); geometry read from the
  multilooked `geom_reference` (576 x 560 grid).
- Stack: 64 interferograms, median coherence 0.53, 0 failed jobs. Sign checked against Sentinel-1.

## Verdict
- The sinking pattern has persisted since 2006.
- In the wells' own period, wells sat on faster-sinking ground: the first independent link between
  wells and sinking in Semarang (map level, not bowl level).
- Detected bowls still do not point at individual wells.
- The east half carries an unremoved ramp, so the "3x faster now" comparison is not yet reliable.
